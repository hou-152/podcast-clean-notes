# 三级笔记

## 产物定位

一份三级笔记要让读者在不打开源稿的前提下，知道作者怎么一步步得出结论，并且能凭笔记里的数字、原话和链接回到源稿的具体位置。

它不是摘要，不是重写稿，不是评论，也不是概念辞典。三级笔记给的是**地图**（这篇材料怎么展开、哪些证据支撑哪些判断）；概念辞典给的是**钥匙**（单个术语的定义、边界与网络位置）。需要术语级理解时，转到概念提取 skill，不要把三级笔记写成辞典。

读者是终身学习者：愿意思考、要求深度、不接受被替他做完判断。

## 任务边界

- 不臆造源稿没有的观点、定义、数据。
- 不添加行动建议、下一步计划。
- 不做价值判断和批评。
- 源稿不确定、专名无法确认、逻辑断裂处，用 `*` 就地标注并写明不确定什么，不猜。

## 写作风格与优先级裁决

Paul Graham 风格（简洁、一针见血、拒绝废话）**只作用于你自己写的字**：过渡句、概括句、每个二级块的收束句、caption。它是对这几类句子的长度要求，不是对整篇笔记的长度要求。

这条风格**不作用于**下面任何一项，它们的去留只由硬标尺决定，与文风无关：

- 源稿内容及其保留量
- 原文引文（`「」` 里的字）
- 作者自创术语
- 数字、阈值、端口、规格、周期、价格、命令、文件名
- 出处链接

**它不是压缩指令。**「这里太长了」永远不构成删除以上任何一项的理由。删一段的唯一合法理由是它属于口头填充、重复、寒暄、流程通知或推广话术。

**优先级裁决：当简洁与保留证据冲突，一律保留证据。**

判断依据是你要删的那一段属于谁：

| 属于 | 处理 |
|---|---|
| 源稿的证据、数字、原话、案例、术语、链接 | 保留，越具体越保留 |
| 源稿的口头填充、重复、寒暄、流程通知、推广话术 | 删 |
| 你自己写的解释和过渡 | 压到最短，一句能说清不写两句 |

## 「三级」是三种功能，不是三层缩进

三个层级各有职能，写的时候按职能填，不按缩进深度填。

**一级（`##`）＝ 论证阶段。** 作者在这一大段里干的事，不是话题名。写「先把 X 看对：它不是 A，而是 B」这类判断句，不写「关于 X」。

**二级（`###`）＝ 推理动作。** 每个二级块的标题必须能对应一个动作：定义、区分、反驳、举证、类比、排序、归因、收束。标题里没有动作就是话题标签，重写。

**三级（列表项）＝ 证据层。** 数字、阈值、命令、路径、文件名、案例过程、对照关系、逐字原话、链接。这一层是可追溯性所在，压这一层等于毁掉笔记。

每个二级块结尾写 1—2 句收束：这段的实际意义，或讲者最有力的那句话。这是你自己的字，按 PG 风格写短。

## 硬标尺

写之前先算出这几个数，写完再算一次。达不到就回 Phase 1 补料，不是在措辞上修修补补。

### 三个闸门（体量单独一项判不出好坏）

三个数都对**清洗稿**算，不对原始转写稿算。分子分母都是非空白字符数。三项全过才算达标，任何一项不过就回 Phase 1 补料，不是在措辞上修修补补。

**为什么不能只看体量**：实测过一份病例，体量 35.6% 正好落在旧区间里，看数字完全合格，但它的原文覆盖率只有 4.5%——32 章里 15 章在笔记里找不到任何痕迹。体量合格掩盖了「凭记忆写摘要」。所以体量降级成粗筛，真正的闸门是下面两个。

**闸门一 · 原文覆盖率下限（防过度压缩）**

源稿有多少比例被逐字带进了笔记。按 12 字窗口滚动比对源稿与笔记，统计源稿被覆盖的字符占比。

| 清洗稿字数 | 原文覆盖率下限 |
|---|---|
| < 8,000 | ≥ 25% |
| 8,000–25,000 | ≥ 22% |
| > 25,000 | ≥ 15% |

实测参照：两份过度压缩病例分别只有 4.5%（笔记）和 3.1%（概念提取）；稳定产出实测 24.8%、68.5%、73.3%、79.1%。低于下限说明你在凭记忆重写，不是在做笔记。

**闸门二 · 照抄率上限（防复读源稿）**

笔记里有多少比例是源稿原文。同样用 12 字窗口。

**照抄率不是独立维度，不设独立上限。** 实测 6 份产出：照抄率 ≈ 原文覆盖率 ÷ 体量（笔记体裁残差 −1.6 ~ +2.7 点）。两者测的是同一批命中片段，只是分母不同——一个除源稿，一个除产出。

所以「照抄率 ≤ 55% ＋ 体量 ≤ 115%」联立等价于「原文覆盖率 ≤ 63.2%」，而高覆盖率正是闸门一要的。实测四份三级笔记全部落在这个无解区里，连覆盖率只有 24.8% 的那份也一样。**内部矛盾的标尺比没有标尺更坏**，它会给出明确、可执行、但方向错误的指令。

**改成看残差，而且只看可合并那一份。** 算出 `预期照抄率 ＝ 覆盖率 ÷ 体量`，与实测照抄率相减。残差为正只可能来自同一段源稿被引了多次，但「多次」有两种，处理方式相反：

- **可合并残差**：同一段源稿在同一个二级块里被重复引用。这是真复读，回去合并。
- **跨块残差**（仪器输出里标作「跨概念」，同一个量）：同一段源稿被几个不同章节各引一次，因为它确实同时支撑几条不同判断。这是正常的，合并了会把其中几条判断的证据抽走。

判据是结构性的，读自己的产出就能判——那段源稿的重复出现，是挤在一个二级标题下，还是分散在几个标题下。

**可合并 > +5 点＝回去合并；跨块不设上限。** 实测两份笔记：总残差 +2.7 那份可合并只有 +0.24，总残差 +0.8 那份可合并 +1.48——总残差低的反而更该改。口径项（覆盖率除源稿、照抄率除产出，两个分母不同带来的几何差）可以为负，那份 +0.8 就是被 −6.96 的口径项压下来的。**拿总残差当上限，等于因为覆盖率达标而判不合格，与闸门一正面相冲。**

**防复读的职责交给结构下限，不交给这个数。** 结构下限与闸门一同向（都要求加自己的字），不会互相顶：每个二级块必须有自己的判断句或收束句；每个一级章节开头必须有过渡句；三级结构必须完整；逐字原话必须带引号且可回源，引号外的都得是自己组织的语言。这四条才是复读时真正消失的东西。

实测参照：概念提取类稳定产出 26.7%，讲座稿笔记 44.7%。分析报告类源稿（数字、表格、链接密集）实测两份：未用本节改法那份 74.8%，用了改法那份降到 63.0%——方向对，但仍超限，见下条。

**闸门与结构下限冲突时：结构下限优先。** 数字、阈值、命令、路径、链接、事故复盘必须逐字进正文；当这些把照抄率或体量顶到上限以上时，**不得删证据来凑数字**。

照抄率偏高的正确改法是加自己的字，不是删源稿的字。照抄率＝被照抄的片段 ÷ 全篇片段：补过渡句、判断句、段尾收束句会抬高分母，照抄率降下来而原文覆盖率不变；删证据则分子分母同时降，照抄率几乎不动，而闸门一直接塌。实测病例：一份产出为追上限连续往回删，36,256 字节降到 19,482 字节，原文覆盖率从 40.0% 跌到 33.2%——两个闸门一起变差。

加完自己的字仍然超限，就带着超限交，并在自检里写清楚「超限」三个字、超多少、哪些证据不能删。**隐瞒超限比超限本身严重得多**——数字是用来判断到底是产出错了还是标尺错了的，盖住就把这个信号弄丢了。

**「我的源稿数字密集，所以上限不适用」不成立。** 实测把产出里的链接、表格行、数字串全部剥掉再算照抄率：分析报告两份分别只降 4.5 点和 4.0 点（63.5%→59.0%、74.8%→70.8%），讲座稿两份几乎不动（−0.0 与 +1.4 点）。强制逐字内容只解释约 4 点，而体裁间差距是 20 点——剥干净之后那份仍有 59% 是逐字散文。所以照抄率超限基本上不是被强制逐字顶上去的，是复述段落太多。改法要落到具体段落：把整段复述改写成「判断句＋证据」结构，不是在段尾追加几句判断了事。

**闸门三 · 体量区间（粗筛）**

| 清洗稿字数 | 保留率区间 |
|---|---|
| < 8,000 | 70%–130%（实测第 1 份 129.4%，过；贴上限 0.6 点。第 2 份 133.0%，FAIL，与第 1 份同源稿，见该段） |
| 8,000–25,000 | 60%–135%（实测合格：112.4%、117.8%） |
| > 25,000 | 45%–90%（上限与下方「上限允许超过 100%」自相矛盾；本档分母干净的实测 133.0%，FAIL，见该段） |

上限允许超过 100%：严格执行「每段至少 3 行落点、每个二级块 2 条证据＋1 条逐字原话、术语一个不丢」之后，笔记体量本身就会接近甚至超过源稿。旧表 28%–65% 的上限与这些下限直接矛盾，那是标尺算错了，不是产出错了。

标「推断」的档没有实测样本，实际跑到时用真实数字回填，不要把推断值当已验证的。三档现在都有实测样本，但样本独立性弱于字面：`< 8,000` 与 `8,000–25,000` 两档用的是同一篇文本——`小档_源稿.md`（6,937 字，md5 `c92b5f7a2611`）就是 `长任务_源稿.md` 的前 6,937 字（`小档 == 长任务[:6937]` 为 True，20 字窗重叠 100.0%），是一篇文本量了两个长度，不是两个体裁；`> 25,000` 档已有一份分母干净的实测（见下段），但**仍没有自然成文长文样本**，那份也是拼接稿。回填只是把实测数记下来，没有动上下界。

**`> 25,000` 档：这一格曾回填过一个「实测 126.5%」，现已撤回——那份样本的源稿是坏夹具。** 那份源稿由人工拼接而成，本应是「长任务 14,879 字 + openclaw 13,180 字 = 28,059 字」，实测却是 42,954 字，差 14,895 字恰好又是一份长任务全文（14,879 字）；用其首 200 字做指纹在源稿里命中 **2 次**，长任务全文作为整串在该源稿中出现 **2 次**，openclaw 全文 **1 次**。也就是说长任务被写了两遍。（此处原写「12 字窗口自重复占比 42.2%」，已删：窗口 5–12 × 全局与分块 × 剥／留空白共 31 种定义全试过都复现不出，最接近的最大偏差仍有 20.9 点，且偏差方向在四份样本间自相矛盾。）后果是分母虚高，两个方向同时失真：覆盖率 84.7% 去重后落到 79.4%（−5.3 点，因为源侧两份副本都被算成已覆盖），而体量 ＝ 产出 ÷ 源稿，分母虚高使 **134.6%**（源 42,954 字／产出 57,802 字）成为**低估**。所以这份样本不能校准本档，写手交付的产出本身没有问题（覆盖率、段内片、过渡句、链接余量都很大），是夹具错了。**本档要等一份真正的 25,000+ 单篇源稿。**

这构成第三份独立证据：一是从结构下限倒推（90% 要求笔记比源稿短，而每二级块 2 证据＋1 逐字、每段 ≥3 行落点的下限相乘只会推高体量）；二是本会话七份合格样本体量全部 >100%，最低 112.4%，代入本档全部 FAIL；三是本档目前唯一分母干净的实测：`大档v2_源稿.md`，28,148 非空白字，md5 `de6db81d874f`，成分为长任务 ×1 ＋ openclaw ×1（长任务全文整串仅出现 1 次，不含坏夹具的重写缺陷），与两篇相加 28,059 字差 +89，是标题与分隔符；其产出体量 **133.0%**，超本档 90% 上限 43 个点，判 FAIL，而同一份产出其余六项判据全过（覆盖率 73.9%／下限 15%，段内最低 60.7%／低于下限 0 片，可合并残差 +1.0／跨概念 +6.4／口径 −2.8，过渡句 13/13，引文 283/283，链接 17/17，实质章 59／零贡献 0／薄弱 0）。**唯一不合格的那一项，正是本档自陈算错的那一项。** 它的限度也要一并读：它仍是拼接稿而非自然成文长文，跨概念残差 +6.4 是可合并 +1.0 的六倍多，主题重叠确实抬高了跨块项——所以它只能证明 90% 这个界**判错**，不能用来**定新界**。**但界仍不改**：单份样本不足以定界，且这份源稿是两篇文章拼接（前 227 行长任务成本分析、后半 OpenClaw 讲座），不是自然成文的 28k 长文，两篇主题重叠会抬高跨块项。改上下界要等自然长文样本，且属产品阈值，须由人决定。

**`> 25,000` 档的 45%–90% 与上一段自陈直接矛盾，不要照它改产出。**上一段说「上限允许超过 100%」，理由是结构下限（每段 ≥3 行落点、每个二级块 2 证据＋1 逐字、术语一个不丢）本身就把体量推到 100% 以上；而这一档的上限是 90%，低于 100%，正是上一段判为「标尺算错」的那种形状。实测佐证：本次会话五份判据全过的产出体量为 112.4%／117.8%／122.5%／129.4%／132.4%——把它们代入 45%–90% 会全部判不合格。本档已经跑过一份分母干净的样本，不是待跑：`大档v2_源稿.md`（实测 28,148 字）→ `大档v2_三级笔记.md`（实测 37,447 字），实测体量 133.0%，超 90% 上限 43 个点判 FAIL，同一份产出其余判据全过（明细见上段）。所以命中这一档时，别为满足 90% 去删证据——这个上限已知判错。但**矛盾就留在这里没解**：单份拼接样本只能证明界判错，不能用来定新界；改上下界属产品阈值，须由人决定，在人裁决之前本表 45%–90% 维持不动，命中本档的合格产出仍会被判 FAIL，如实报超限即可。

**闸门二超限的改法会把体量顶上去，此时闸门三让位。** 闸门二的正解是加自己的字抬高分母，加字必然抬高体量——两条规则会互相顶。判定顺序：闸门一必须过（它防的是掏空正文，没有退路）；闸门二是真正的复读探测器；闸门三只是粗筛，当体量超限**是因为执行了闸门二的改法**（照抄率在降、覆盖率没掉、引文与章节贡献都健康），按超限如实报，不要靠删证据把体量压回区间。

实测病例：一份分析报告源稿的笔记，照抄率从 74.8% 降到 63.0%，原文覆盖率 79.1%→73.3%（证据基本没删），体量 109.7%→117.8%。照抄率降了 11.8 个点，代价是体量超上限 3 个点。两个数一起看才知道发生了什么，单看体量会把这次改进判成退步。

**< 8,000 档实测第 1 份：129.4%，七条判据全过（覆盖 73.8%／下限 25%，段内最低 42.4%，可合并残差 +0.3，引文 39/39，链接 12/12，过渡句 9/9）。** 但它是先交 152.5% 再改到 129.4% 的：初稿把二级块切成 26 个，每块只摊 267 源字，而结构下限按【块】计价（每块 2 证据＋1 逐字＋收束），块越密自己的字越多——初稿自己的字/源字 66.7%，8,000–25,000 档四份的均值是 45.8%。并到 18 块（每块 385 源字，仍低于中档均值 482）后体量落到 129.4%，覆盖率 76.6%→73.8% 仍是下限的 2.95 倍，且 18 块里「证据 < 2」与「逐字 < 1」各 0 个——义务一条没减，降的是重复和框架前缀。剥掉固定外壳（自检块、关键术语、待补）后初稿仍有 130.7%，所以超限不是模板开销造成的。**单份样本，不足以据此放宽 130% 这个界**；再跑几份短源稿后按体裁回填。

**< 8,000 档实测第 2 份：133.0%，超上限 3 点，FAIL；初稿即交付，未测量。** 这是一次真冷启动：写手只拿到本 SKILL.md 与小档源稿，禁读任何既有笔记、测量脚本、工作文件，也未被告知任何阈值。厚度很好——产出 9,228 字，覆盖率 75.0%（下限 25%）、段内最低 43.8%／低于下限 0 片、引文 53/53 全数回源命中、链接 12/12、过渡句 5/5、平均指纹覆盖 98.7%、零贡献章 0。但两项 FAIL 同一个根因（自报行被零填，详见「输出格式」后一段）：体量 133.0%，以及自报字数「产出 0」对实测 9,228（偏 −100%）。体量超限是这个根因的下游——没量过，就不可能像第 1 份那样从初稿 152.5% 改到 129.4%。它的限度：源稿与第 1 份同源（小档＝长任务前 6,937 字），不是新体裁，所以它加强的只是「上限在初稿阶段普遍顶格」这个观察，**不满足**上一段提的「再跑几份短源稿后按体裁回填」——那要求不同源稿、不同体裁。**不许据此放宽 130%。**

**本档 115% 上限是讲座稿校准的，对数字密集的分析报告可能偏紧。** 实测那份分析报告笔记里，链接＋表格行＋数字串合计约占产出 12.7%，剥掉后体量从 117.6% 落到约 102%——落回区间内，说明这一档上限对这类源稿确实偏紧。多跑几份分析报告后按体裁分档回填，不要凭单一体裁的样本收紧上限。**但这条只对闸门三成立，不能拿来给闸门二免责**：同一次实测里，剥掉这些内容对照抄率只有 4 点影响。

闸门要的数一次算出来。覆盖率、照抄率、残差拆分都手算不出来，必须跑：

```bash
python3 - 清洗稿.md 笔记.md <<'PY'
import sys, re
L = 12
ws = lambda t: re.sub(r'\s', '', t)
raw_s = open(sys.argv[1], encoding='utf-8').read()
raw_o = open(sys.argv[2], encoding='utf-8').read()
a, b = ws(raw_s), ws(raw_o)
A = {a[i:i+L] for i in range(len(a)-L+1)}
B = {b[i:i+L] for i in range(len(b)-L+1)}
f = bytearray(len(a))
for i in range(len(a)-L+1):
    if a[i:i+L] in B: f[i:i+L] = b'\x01'*L
c_src = sum(f)
head, hid, pos = [0]*len(b), 0, 0
for ln in raw_o.split('\n'):
    st = ln.strip()
    if re.match(r'^#{1,6}\s', st) or re.match(r'^\d+\.\s*\*\*', st): hid += 1
    n = len(ws(ln))
    for i in range(pos, min(pos+n, len(b))): head[i] = hid
    pos += n
f_all, f_fph, f_glb = bytearray(len(b)), bytearray(len(b)), bytearray(len(b))
sg, sf = set(), set()
for i in range(len(b)-L+1):
    w = b[i:i+L]
    if w not in A: continue
    f_all[i:i+L] = b'\x01'*L
    if w not in sg:
        sg.add(w); f_glb[i:i+L] = b'\x01'*L
    k = (w, head[i])
    if k not in sf:
        sf.add(k); f_fph[i:i+L] = b'\x01'*L
n_all, n_fph, n_glb = sum(f_all), sum(f_fph), sum(f_glb)
cov, cp, vol = c_src/len(a)*100, n_all/len(b)*100, len(b)/len(a)*100
exp = cov/vol*100 if vol else 0.0
print(f"清洗稿 {len(a)} 字 / 笔记 {len(b)} 字 / 标题 {hid} 个")
print(f"覆盖率 {cov:.1f}%  照抄率 {cp:.1f}%  体量 {vol:.1f}%  预期 {exp:.1f}%")
print(f"残差 {cp-exp:+.1f} 点 ＝ 可合并 {(n_all-n_fph)/len(b)*100:+.1f} ／ 跨块 {(n_fph-n_glb)/len(b)*100:+.1f} ／ 口径 {(n_glb-c_src)/len(b)*100:+.1f}")
K = 16
sl = [(s+1, sum(f[len(a)*s//K:len(a)*(s+1)//K])/(len(a)*(s+1)//K-len(a)*s//K)*100) for s in range(K)]
lo = min(sl, key=lambda x: x[1])
print(f"段内覆盖率 等分{K}片：最低 第{lo[0]}片 {lo[1]:.1f}%")
print("  各片 " + " ".join(f"{v:.1f}" for _, v in sl))
PY
```

**覆盖率算的是「源稿被覆盖的字符占比」，不是「12 字窗口的集合占比」。** 集合写法更短、看着等价，实测低报 13–24 点：同一份三闸门全过的笔记，集合占比只给 44.0%，字符占比 68.5%。照集合写法自评，会把达标产出判成严重不达标，接着去多抄原文。不要把它改回集合写法。

### 段内覆盖率下限

**全局达标不算达标。** 段落地图里每一段单独达标，任何一段的原文覆盖率低于**闸门一下限的 0.7 倍**即判尾部塌缩，回补该段。

这条专门防前密后疏：源稿后半程被读薄时，全局数字往往仍然合格。

段内覆盖率**由上面那个计算器直接给出**（`段内覆盖率 等分16片：最低 第k片 Y%`），不要手算。

原先这里写的是「逐段数笔记字符除以该段源字符量」，那算出来的是**保留率**，不是覆盖率——两个量差 30 到 196 点（实测六份产出：+30.0／+43.9／+44.5／+47.2／+59.5／+195.9）。拿保留率去比覆盖率下限，六份**全部通过**，包括覆盖率只有 24.8% 的那份；换成覆盖率口径，它立刻不达标。所以那个配方让这条防塌缩的规则完全空转，别再用。

等分 16 片是段落地图的近似：地图是工作文件、不进笔记，所以只从（清洗稿、笔记）两个文件出发时拿不到段边界。K=16 有实测依据——K=12–25 全区间在 8 份样本上判定一致（切片 1098→527 字），16 是余量最大的点。代价是可能切在噪音段上：某片低于下限时，先拿它的源字符区间对段落地图核一下是不是噪音段，是就在对账表里写明理由，不是就回补该段。

### 结构下限

- 段落地图每一段至少 **3 行正文落点**。做不到就在对账表里显式标为噪音并写理由，不能默默跳过。
- 每个二级块至少 **2 条具体证据 ＋ 1 条逐字原话**。
- 作者自创术语一个都不能丢。源稿里的人工标记（下划线、加粗、高亮、批注）视为已判定的重点，优先逐字进正文。
- **模板／目录／元数据合计 ≤ 全文 10%**。目录不得复制正文标题——正文标题已经是目录，再抄一遍只是占额度。

### 必须逐字进正文，不许概括

数字、阈值、端口、规格、周期、价格、命令、文件名、**链接与出处**、失败案例与事故复盘的完整过程（谁在什么情况下踩了什么坑、怎么发现、怎么恢复）、对照关系。

对照关系保持表格或 A/B 结构。把「A 快但不可控，B 慢但可控」拆成两条平铺 bullet，对照就没了。

链接这条最容易在无声中违约：源稿里有多少条 http 出处，笔记里就应该有多少条能用的。写完数一次。

```bash
grep -c 'http' 清洗稿.md 笔记.md
```

### 语境还原

每个案例带上它的处境：谁、什么时候、因为什么被提出来。脱掉语境的案例会退化成一句抽象结论，读者无法判断适用范围。

## 执行流程

### Phase 0 侦察

先做便宜的事。

1. 量清洗稿非空白字符数，据此从三个闸门的表里取出本次的四个数字，写下来——后面每个阶段都要用：原文覆盖率下限、体量区间、段内下限（＝原文覆盖率下限 × 0.7）。照抄率不取阈值，交付时算残差，并把残差拆成可合并与跨块两项——判决只看可合并那一份。
2. 判定材料类型：`clean_article`（可读文章、论文、研报、课程稿）／`raw_transcript`（语音转写、直播回放、会议记录、时间戳混乱）／`calibration_text`（用户给的校准稿、术语修正、高亮批注）。
3. `raw_transcript` 必须先清洗再做笔记，绝不从噪音稿直接起草。清洗只删口头填充、时间戳、设备杂音和明显识别错误，合并同义重复；保留讲者语气、长论证段落、原始术语。清洗稿单独存文件，之后的保留率都对它算。
4. `calibration_text` 只用于修正术语、专名和边界，不替代主源。除非用户明确说它才是 source of truth。
5. **声明单一主源文件名。** 多来源时写清哪个是主源，引文只从主源摘；跨文件取引文必须标出处文件。框架从一份文件取、引文从另一份文件取而不交叉复核，会产出与源稿拼写和数字都不一致的笔记。
6. 按自然边界（标题、章节、议题转折）切段，产出**段落地图**。

段落地图是文件，不是脑内印象。字段就这四个：

| 段号 | 定位 | 主题 | 字符量 |
|---|---|---|---|
| 1 | L5–L37 | OpenClaw 的本质：本地 AI 网关 | 1820 |
| 2 | L39–L67 | Gateway、消息流、工作区文件 | 2140 |

`定位` 用源稿行号区间或原文标题，保证能回查。`字符量` 是这段的非空白字符数，段内下限由它乘出来。

### Phase 1 逐段精读

防压缩主力。每段产出一条结构化记录。字段名固定，不要改名、不要省字段：

```json
{
  "seg": "2",
  "src_file": "01_清洗稿.md",
  "src_lines": "39-67",
  "src_chars": 2140,
  "min_note_chars": 525,
  "main_claim": "本段的主判断，一句话，必须是判断不是话题",
  "move": "论证动作：定义/区分/反驳/举证/类比/排序/归因/收束",
  "evidence": ["带数字、路径、命令、案例过程的具体证据，逐条"],
  "verbatim": [{"text": "逐字原话，不含外层引号", "src_line": 41}],
  "terms": ["作者自创或本文特有的术语，用原文写法"],
  "images": [{"path": "原始路径或 URL，逐字", "caption": "看这张图的什么", "supports": "支撑哪条判断"}],
  "droppable": ["本段可弃项及理由"]
}
```

`verbatim[].src_line` 是硬机制：原话必须能给出行号。给不出行号的句子不是原话，写进 `evidence` 当转述，不要放进 `verbatim`。

`min_note_chars` ＝ `src_chars` × 段内下限。本段记录里 `evidence` ＋ `verbatim` 的字符合计低于这个数，就是这段没读完，重读该段，不要往下走。

**源稿超过 15,000 字时，分段派 subagent，每个 agent 领 3—5 段。** 八个 agent 各读 1.1 万字，不会像单个上下文吞 9 万字那样把尾部压扁。

派发时 prompt 里必须写死这几件事，缺一样都会让 agent 自行压缩：

```
你负责第 N–M 段。源稿：<路径>，你的区间：<行号区间>。
只读并只回你负责的段，不要概述全文，不要写笔记正文。
按下面 schema 逐段返回 JSON 数组，字段名一字不改，缺字段视为未完成：
<粘贴上面的 schema>
每段的 evidence + verbatim 字符合计不得低于该段的 min_note_chars（已在 schema 里给出）。
verbatim 每条必须给 src_line，你无法定位行号的句子不许放进 verbatim。
数字、阈值、端口、命令、文件名、价格、周期、链接一律逐字抄，不许概括、不许换算、不许四舍五入。
作者自创术语用原文写法保留，不要替换成通用学术词。
```

回收后按 `seg` 排序拼装，检查段号连续、无缺号，每段 `min_note_chars` 都达标。缺号或不达标的段单独补派。

**无 subagent 能力时的串行退路**：逐段显式深读，一段一条记录，每写完一条就核对 `min_note_chars`。不要一次读完全文再回忆着写——压缩会发生在推理内部，你看不见也回读不了。

### Phase 2 结构重建

从段落记录反推论证骨架，不按源稿时间线机械排列。

1. 把各段 `main_claim` 排在一起，找出作者真正的论证顺序，据此定一级块。一级块标题写判断句。
2. 每个一级块下按 `move` 分二级块，标题带推理动作。
3. 各段的 `evidence` `verbatim` `terms` 落进对应二级块的三级列表。
4. 每个一级块开头写 1—2 句过渡，说明这段与上一段的关系（承接／转折／递进／对照）。
5. 全文开头写一句总纲：这篇材料真正要证明什么。用 `>` 引起。

拼装时不要合并证据。两条数字不同的证据合成一句「多项数据表明」，就是在这一步把笔记压瘦的。

### Phase 3 回源核对

**这是唯一真正防压缩的验证机制。** 自评「我觉得没压过头」不可靠，必须锚到源稿。

先分清两类引号，这决定核对怎么做：

- **「」＝ 逐字引文。** 必须在源稿逐字存在，必须能给行号。
- **你自己的说法、命名、强调，一律用加粗，不用「」。** 你写的「行为控制台」这类概括如果套上引号，读者会当成作者原话，而你自己回头也分不清。
- **`>` 引用块只放源稿逐字整句，不放你自己的话。** 自检行、一句话总纲、过渡句都不用 `>`。两种用途共用一个记号，回源核对就分不出哪条本该在源稿里找得到——实测三份产出的 9 条「引文未命中」全部出自这一处混用，没有一条是真编造。

然后跑三件事：

**一、逐条 grep 引文。**

```bash
python3 - 清洗稿.md 笔记.md <<'PY'
import sys, re
src = open(sys.argv[1], encoding='utf-8').read()
note = open(sys.argv[2], encoding='utf-8').read()
bad = 0
for q in re.findall(r'「([^」]{4,80})」', note):
    if q in src:
        continue
    t = q.strip('。，；、！？…"\'')
    tag = '近似：收紧为无标点片段' if t in src else '伪引文：去引号改转述'
    print(f'{tag} → {q}')
    bad += 1
print('待处理引文', bad)
PY
```

两种处理各自动作不同，不要一刀切：

- **近似**（去掉首尾标点后能命中）＝ 你把源稿的分号改成了句号，或从长句中间截断。**收紧引号范围到真正逐字的那一段**，别把它当伪引文删掉，那会误杀真证据。
- **伪引文**（怎么都命中不了）＝ 它是你的概括或几处原话的拼接。去掉「」改成转述，或改成加粗；如果这句判断有源稿依据，把真正的原话找出来替换。

注意：`grep -o` 在多字节上下文区间上不可靠，用上面的 python，不要用 `grep -o` 抽引文。定点确认单条时用 `grep -n -F '片段' 清洗稿.md`。

**二、对账段落地图落点。** 逐段填这张表，它是工作文件，不进笔记：

| 段号 | 源起止行 | 源字符量 | 笔记起止行 | 笔记字符量 | 段内覆盖率 | 段内保留率 | 落点行数 | 判定 |
|---|---|---|---|---|---|---|---|---|

`段内覆盖率` 是判定用的那一列，取计算器打出的等分片值（低于下限的片，用它的源字符区间对上本表的段号）。`段内保留率` ＝ 笔记字符 ÷ 源字符，只作参考不判定——它恒大于覆盖率 30 点以上，当判据会让这一列永远合格。

任何一段落点少于 3 行、或**段内覆盖率**低于下限，回 Phase 1 重读该段。标为噪音的段要写理由。

**三、跑三个闸门，数链接，量模板占比。** 三个闸门全过，链接一条不少，模板占比在标尺内。

五类不达标各有各的补法，别互相代替：原文覆盖率偏低＝回源把证据逐字抄回来，不是换措辞；照抄率超限＝把复述段落改写成判断＋证据结构，不是删证据；单段偏低＝重读那一段；链接缺失＝回源把出处抄回来；模板超额＝删元数据和目录，不是删正文。

### Phase 4 交付

自检写成极短一段放文件头，**不超过 5 行**，只写数字和待办：

```
自检：清洗稿 13180 字 → 笔记 14811 字
闸门一 原文覆盖率 68.5%（下限 22%）｜闸门三 体量 112.4%（区间 60%–135%）｜照抄率 63.6%，预期 60.9%，残差 +2.7＝可合并 +0.2／跨块 +2.1／口径 +0.4（可合并 ≤ +5 点，过）
段内最低：第 k 段 Y%（下限 15.4%，逐段实测填入）
引文 62 条回源命中 61；源稿 http 出处 0 条
模板占比 8%；图片 0 张（原因：源稿与图池均无可用图）
待核：`LE 索引` 专名无法从源稿唯一确认
```

不写状态标签，不写证据账本，不写过程叙述。数字不达标就不要交付，回去补。

## 图片

图片是阅读脚手架，帮读者更快看懂正文，不替正文干活。

**保留**：框架图、数据图、流程图、对照表、讲义结构页。
**删除**：装饰图、人像、logo、纯文字截图（把里面的文字抄进正文即可）。

**配额**：每个一级章节 ≤ 2 张，全文 ≤ 12 张。

**图从哪来**：源稿基本不带图——图在课程幻灯片资产、录屏截图或讲者给的素材包里。动笔前先找图池：看源稿同级或上一级有没有 `assets/`、`slides/`、`screenshots/`、`img/`，文件名通常带讲次与序号（如 `xxx_01_slide_07.png`）。按序号与正文章节顺序对齐，挑出本篇真正用得上的那几张。找不到图池，就在交付自检里写「图片 0 张，原因：未找到可用图池」——**0 张必须是显式判定加理由，不能是默默交空。**

**每张必须**：

- 有说明性 caption，写清「看这张图的什么」＋ 它支撑哪条判断。`![](...)` 这种空 caption 不算过关。
- 紧跟被它支撑的那条判断之后，不聚在章节末尾。
- 原始路径／URL 逐字保留，不改写、不下载、不新建目录。两种合法来源：本地相对路径 `../assets/xxx.png`，远程课程平台 CDN 链接。

写到 git 镜像目录时 `assets/` 可能被 gitignore，图片解析不出来。这是已知现象，**不要因此改路径或复制文件**——路径逐字保留优先。

**两条红线**

1. **图片不得承担正文职责。** 删掉全部图片后笔记必须仍然读得通。禁止「见图」「如下图所示」式表述，禁止把关键信息只写在 caption 里。图里的数字、结论、层级关系要在正文写出来。
2. **图片不得顶掉过渡句。** 图片放在章节开头会挤掉那 1—2 句过渡。图片前后都要有文字，章节开头永远先写过渡句。

```markdown

- \*[哪里不清楚，缺什么，为什么无法确认]
```

**自检头里每一个数都必须先量后写。** 交付前拿定稿实际跑一遍「硬标尺」那个计算器、引文核对脚本和 `grep -c 'http'`，用真实输出填这六行。Phase 0 第 1 步取的四个数（覆盖率下限、体量区间、段内下限）是读档表得来的**阈值**，不是实测值，填对它们不等于量过产物。

**零填等于没做，判交付失败。** `0000 字`、`00.0%`、`000.0%`、`+0.0` 这类形状一律视为未测。它比留 `[N]`／`待填`／`TODO` **更坏**：占位符一眼能看出没填，零值能通过「占位符已清空」这类检查，读起来像真测过。冷启动实测的分界线干净得像刀切——凡是读档表或数源稿侧的全填对了（清洗稿 6,937 字、下限 25%、区间 70%–130%、段内下限 17.5%、出处链接 12 条、图片 0 张并写了真实原因），凡是需要量产物自身的全是零（笔记字数、覆盖率、体量、照抄率、残差、段内最低、引文条数、模板占比），且一个占位符都没留。量不出来的那一项，如实写「未测」并给理由，不许拿 0 冒充。

写回 Logseq 时沿用图谱现有外壳（`class::` `tags::` `bok::` 这些属性块、`1️⃣ why` `2️⃣ what` `3️⃣ how` `4️⃣ how good` 分区），正文放在 `3️⃣ how` 下面，自检放 `4️⃣ how good`。外壳全部计入 10% 模板额度，所以外壳越固定，正文越要够厚。`## 原文拆分依据` 只写一句「按什么切段」，段落地图和对账表留在工作文件里，不要粘进页面——那正是把目录抄成正文标题的复制品。

## 不要做

- 不从原始转写稿直接起草。
- 不把作者术语替换成通用学术标签。
- 不把承载推理的长段落切成碎 bullet；长段落承重就保留长段落。
- 不保留每一个故事，只保留支撑论证的故事。
- 不把数字换算、约等、四舍五入，不把「18789」写成「默认端口」。
- 不用「多项数据表明」「诸多案例说明」替代具体证据。
- 不给没回源命中的句子加「」。
- 不在标尺不达标时交付。
