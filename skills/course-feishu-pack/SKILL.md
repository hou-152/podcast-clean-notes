# course-feishu-pack：课程整理 → 飞书交付流水线

把一份学习材料（课程稿、讲座转写、直播稿）从原始文件一路做成飞书在线文档并交付回执。每条站点有固定命名和验收动作，材料已经在中间的站点时，从下一站继续，不重复劳动。

## 站点总览

| 站 | 动作 | 产物 |
|---|---|---|
| 0 | 输入记账：源文件 SHA-256、主题与输出目录定案 | `00_原始转写.txt`（源 docx 另存时） |
| 1 | 洗稿（ASR 校订表法） | `01_清洗稿.md` |
| 2 | 三级笔记（v3 标准，读 `references/note-taking-standards.md`） | `02_{主题}_三级笔记.md` |
| 3 | 概念提取（v3 标准，读 `references/concept-standards.md`） | `03_{主题}_概念提取.md` |
| 4 | 引文校验：03 的引号内容、02 的「」内容必须逐字命中 01 | 校验报告（命令输出即可） |
| 5 | DOCX 打包：`scripts/build_feishu_docx.py` | `{主题}_三级笔记_概念提取_原文_飞书导入版.docx` + `manifest.json` |
| 6 | 飞书导入（`lark-cli drive +import`，先 `--dry-run`） | 飞书在线文档链接 |
| 7 | 在线回读核验 + 回执 | `FEISHU_DELIVERY_RECEIPT.md` |

## 命名与输出位置

- 主题：默认取源文件名去掉扩展名与「_原文」后缀；用户给出主题时用用户的。
- 输出目录：默认源文件所在目录；用户指定时跟随。不改用其他目录拼装。
- 固定命名（示例主题 = 8月29日 第二课）：

```text
00_原始转写.txt
01_清洗稿.md
02_8月29日 第二课_三级笔记.md
03_8月29日 第二课_概念提取.md
8月29日 第二课_三级笔记_概念提取_原文_飞书导入版.docx
FEISHU_DELIVERY_RECEIPT.md
```

- 目标文件已存在时停止并询问，不覆盖源文件或既有成品。源文件全程只读。

## 站 0 · 输入记账

1. 源文件若为 docx 且正文只有转写文本，先转存为 `00_原始转写.txt`（保留发言人＋时间戳原格式），docx 仅作源归档；记下两者 SHA-256。
2. 源文件若已是 txt 转写稿，直接命名 `00_原始转写.txt` 并记 SHA-256。
3. 用户已给清洗稿／三级笔记／概念提取时，跳过对应站点，记作既有产物，从下一站继续。
4. **并发防护**：开工前检查输出目录内是否有并行处理痕迹——`02a_*`／`02b_*`／`AB_TEST*` 等 A/B 或他人产物、目标文件 mtime 在本会话期间跳动、目录出现已存在的 `01/02/03` 但内容与来源不符。发现任何一项立即停下询问，不覆盖、不继续写。同一目录禁止两个 Agent 同时跑本流水线（2026-09 实测踩踏：并行流程互相覆盖 02/03/回执并删除彼此的飞书文档）。

## 站 1 · 洗稿（ASR 校订表法）

1. 文首放「清洗说明」块，固定四项：源文件名＋SHA-256；清洗说明（去发言人标记与时间戳，按口语原顺序整理成段；修复 ASR 错别字、重复与口误；不增删观点与信息）；统一校订表；存疑保留清单。
2. 通读全文建校订表：同一实体以多种错写反复出现时，按上下文与领域知识确证，收敛为一词。
3. 无法确证的模型名、平台名、人名 → 存疑保留，原样进清单，不猜。
4. 成段整理：保持口语原有顺序与观点，不加总结、不做文风改写。洗稿＝清洗，不是改写。
5. 质量门：无时间戳／发言人残留；完整、可读、保留原意。
6. 源已是完整、可读、保留原意的清洗稿时，跳过本站，记为 `cleaned_source` 直接沿用。

## 站 2、3 · 同源分叉（三级笔记、概念提取）

- 等 `01_清洗稿.md` 定稿后，两站各自直接读同一份 `01_清洗稿.md`；两份都缺时可以并行。
- 禁止互相读取产物，禁止「三级笔记 → 概念提取」或反向串联。
- 两级标准并存：**V1 为默认**（本机 `~/.agents/skills/note-taking-pro/SKILL.md`、`~/.agents/skills/concept-learning/SKILL.md`，2026-09-05 用户裁定：轻量可扫读优先）；v3 留档于 `references/note-taking-standards.md`、`references/concept-standards.md`，用户明确要证据底座型产物时按 v3 跑。
- 三级笔记默认执行 V1 note-taking-pro：Agentic Reading 三条判断、三级论证骨架（一句话主旨 → 作者试图回答的问题 → 骨架 → 边界）、篇幅自然生长不设数字闸门、引号内只放逐字原话。产出以可快速扫读为准（实测参照：V1 体量约 40%，第 1 课）。
- 概念提取默认执行 V1 concept-learning：承重判断＋淘汰测试、每概念 context＋费曼一下、Mermaid 分层架构图（只画原文能支持的边）。
- 两份标准较重，按需读取对应文件，不把内容重复抄进回复。

## 站 4 · 引文校验

03 的所有引号引用、02 的「」内容必须是 `01_清洗稿.md` 的逐字子串。用 Python 校验，不用 `grep -o` 处理多字节：

```bash
python3 - <<'PY'
import re
src = open('01_清洗稿.md', encoding='utf-8').read()
for path in ['02_8月29日 第二课_三级笔记.md', '03_8月29日 第二课_概念提取.md']:
    text = open(path, encoding='utf-8').read()
    quoted = re.findall(r'「([^」]+)」', text) + re.findall(r'“([^”]{4,})”', text)
    for q in quoted:
        if q not in src:
            print(f'{path}: 未命中 → {q[:40]}')
PY
```

不匹配时退回对应站点修正后再继续。

## 站 5 · DOCX 打包

```bash
python3 scripts/build_feishu_docx.py \
  --title "8月29日 第二课" \
  --notes "02_8月29日 第二课_三级笔记.md" \
  --concepts "03_8月29日 第二课_概念提取.md" \
  --source "00_原始转写.txt" \
  --output "8月29日 第二课_三级笔记_概念提取_原文_飞书导入版.docx"
```

- `--source` 支持 txt（转写文本，发言人＋时间戳行做弱化样式）与 docx（原文部分完整保留原文档正文与图片，脚本自带 c14n／media／rels 一致性自验）。
- 笔记／概念里引用的图片（`assets/…` 相对路径）自动嵌入；缺图时报错退出，不静默丢图。
- 成功输出：`manifest.json`（各输入与输出 SHA-256）+ 打印校验行。产物 docx 无图异常、无 Mermaid 源码残留（mermaid 代码块跳过，正文保留替代说明）。

## 站 6 · 飞书导入

细节、命令与失败处理读 `references/feishu-delivery.md`。要点：

1. 先 `--dry-run` 检查标题与目标，再真实导入（用户请求中已明确「上传／发飞书」时，dry-run 后直接执行并汇报结果）。
2. `lark-cli drive +import --file <docx> --type docx --name <标题>`，目标个人云盘根目录（我的文档）。
3. 取回链接（`lark-cli drive +inspect` 展开 token），记录导入状态；异步任务用 `+task_result` 轮询。
4. 不覆盖既有飞书文档；历史同名页面存在时先报告链接，用户决定是否新建。

## 站 7 · 在线回读核验 + 回执

1. 用 lark-cli 回读在线文档：标题、第一部分｜三级笔记、第二部分｜概念提取、第三部分｜原文、每部分至少一个关键锚点（站 2／3 主题句、核心概念名）、图片抽查。
2. 写 `FEISHU_DELIVERY_RECEIPT.md`，模板见 `references/feishu-delivery.md`：交付时间、飞书标题、链接、导入状态、回读核验清单、本地成品 SHA-256、边界说明。
3. 回执中的 SHA-256 必须与 `manifest.json` 一致。

## 验收（全链完成判定）

同时满足才能报告整套完成：

1. `00`–`03` 均存在且非空；`02`、`03` 来自同一份 `01`（本轮刚生成或用户明确指认同源，不凭文件名猜）。
2. 引文校验零未命中。
3. docx 已生成，脚本自验通过（txt 源：文档非空、三部分齐全；docx 源：原文 body 逐块一致、media／rels 保持）。
4. 飞书在线文档可回读，回执已写，链接与 SHA-256 与 manifest 一致。

任一站失败、输入不完整、顺序不明、目标碰撞或权限不足时停止，保留已完成的独立产物，报告「部分完成」并列出待核问题。

## 授权与停止条件

- 不覆盖本地既有文件与既有飞书文档；写入前有碰撞先报告。
- 真实导入飞书前先 `--dry-run` 并汇报标题与目标位置；用户请求明确包含上传时不重复征求。
- 外部动作（导入、移动、删除、改写线上文档）只做本流水线既定步骤，不做额外线上操作。
- 用户只要单站（只洗稿／只笔记／只概念）或入库到 Logseq／Notion 时，不启动本流水线，路由到对应 Skill。

## 非目标

不负责：纯单站处理、Logseq／Notion／知识库写回、DOCX 之外的其他交付格式、内容改写与发布、视频制作。不引入固定篇幅比例、加分 rubrics 或与验收无关的额外产物。
