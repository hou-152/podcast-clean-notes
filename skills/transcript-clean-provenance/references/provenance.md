# 溯源规约（四条链）

溯源的用途：让清洗稿可信度可审查。四条链各管一段，互代偿不了。

## 链一：源冻结

- 处理前记录源文件 SHA-256；处理全程源文件只读，一字节不动
- 源文件是证据本体：清洗稿的每句话要能回到其中的具体位置
- 结论行写：源文件名＋哈希；产物文件名＋哈希

## 链二：改动对账（修订记录）

- 每处非机械改动（听辨修正、噪声处理、数字拆分）进修订记录：段号｜原→改｜类别｜依据
- 词级收敛集中在校订表；修订记录管「这条原话被动了哪里」——两份互补，不互相代替
- 修订记录不放进清洗稿正文：正文保持可读，对账走独立文件

## 链三：对名（角色 → 真人）

- 原始转写的「发言人序号」是顺序编号，不是身份；角色名只能靠对：自称、他人称呼、课程场景、跨场材料
- 每个写进产物的角色名附「凭什么认出」的依据（可在待对清单查）
- 对不出的：待对占位（「待对·同学A」类）＋识别线索；合对后确认或修正
- 不承诺「所有发言都有正确角色名」；源里没给的身份不造

## 链四：跨场收敛（词表）

- 同一实体跨场的写法收敛依赖一份共享词表：位置在项目内（如语料库根 `词表.md`），有则读、无则建
- 本场新收敛的词条：先查词表先例 → 沿用；无先例 → 本场定 → 记录进词表（含首次出现场次）
- 词表条目写：收敛写法｜曾出现写法｜首次确证场次｜依据
- 词表是追加式的：不删旧写法记录——历史场次的对账需要它们

## 结论行格式（给下游）

结论行**独立落成一个小文件**：`<会话名>_结论行.md`（含结论行＋配套件哈希行）。理由：结论行是给下游和审查者的收据，独立落盘后可被单独引用、单独校验，与修订记录／待对清单同级。文件内容：

```text
[clean-provenance] 源=<文件名> sha256=<12位前缀>｜清洗稿=<文件名> sha256=<12位前缀>｜校订表=<n>条｜存疑=<n>条｜待对=<n>条｜覆盖=完整（零增删核对通过）

---

配套件：`<会话名>_修订记录.md`（sha256 前缀 …）｜`<会话名>_待对清单.md`（sha256 前缀 …）
```

上游（纠错工序）与本模块的分工：上游负责多源互校、取舍、产出「校验后的单一真源」；本模块只对这一个真源做清洗与溯源。

## 门脚本与已知格式边界（2026-10-16 压测更新）

- `trace_check.py` 的工具行剔除支持两种源格式：「发言人N＋时间戳」（腾讯会议）与「发言人（无编号）＋时间戳」（通义听悟）；其它变体（如「说话人」命名）若出现，先核对是否被计入未覆盖，必要时扩展正则。
- 门读数贴线（覆盖率 88%–92%）时先看诊断：常见低估来源是工具行格式未匹配，而非真丢内容。
